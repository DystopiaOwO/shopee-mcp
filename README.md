# shopee-mcp — buyer cart fork

This repository is a fork of [`bintangtimurlangit/shopee-mcp`](https://github.com/bintangtimurlangit/shopee-mcp). It keeps the upstream browser-backed product discovery tools and adds **buyer-side cart reading and opt-in Add to Cart support**.

The project is **unofficial** and is not affiliated with Shopee or Sea Limited.

## What this fork adds

| Tool                   | Purpose                                             | Account side effect |
| ---------------------- | --------------------------------------------------- | ------------------- |
| `search_products`      | Search Shopee products                              | No                  |
| `get_product_detail`   | Read product details                                | No                  |
| `get_product_variants` | List exact variant/model IDs, stock and prices      | No                  |
| `get_cart`             | Read the logged-in shopping cart                    | No                  |
| `add_to_cart`          | Add a selected product/model to the cart            | **Yes, opt-in**     |
| `check_login_status`   | Check whether the saved Shopee session is logged in | No                  |

`add_to_cart` is intentionally limited to the shopping cart. This fork does **not** implement checkout, order placement, delivery-address changes, payment-method changes, or payment submission.

## Why a browser is required

Shopee's buyer web APIs use anti-fraud request signatures generated by Shopee's own web application. The server therefore drives a persistent CloakBrowser/Chromium profile that you log into once, navigates the real Shopee pages, and observes the requests/responses generated by Shopee's own frontend.

For cart writes, the server clicks the real product-page **Add to Cart** control and waits for Shopee's `/api/v4/cart/add_to_cart` response. It does not attempt to manufacture Shopee's signed private API requests itself.

The browser normally needs to run **headed** because Shopee can detect headless automation.

## Install this fork from source

```bash
git clone https://github.com/DystopiaOwO/shopee-mcp.git
cd shopee-mcp
npm install
npm run build
```

The upstream npm package does not contain this fork's cart tools, so use this repository checkout while these changes remain fork-specific.

## Configure Taiwan Shopee

Copy `.env.example` to `.env` and use:

```env
SHOPEE_DOMAIN=shopee.tw
SHOPEE_CART_WRITE_ENABLED=false
```

When the domain ends in `.tw`, the browser automatically defaults to `zh-TW` and `Asia/Taipei`. You can override them with `SHOPEE_LOCALE` and `SHOPEE_TIMEZONE`.

### Enable Add to Cart

Cart mutation is deliberately disabled by default. After you have tested login, product search, variants, and `get_cart`, opt in locally:

```env
SHOPEE_CART_WRITE_ENABLED=true
```

Restart the MCP server after changing the flag.

## Log in once

From the source checkout:

```bash
npm run login
```

A browser window opens. Log into the Shopee account you want the MCP server to use, then follow the terminal prompt. The persistent profile is stored under `~/.shopee-mcp/chrome-profile` by default.

**Treat that directory like a password.** Never upload or commit it.

## Register with an MCP client

After building, point the MCP client at `build/index.js`. Example on a desktop with a graphical display:

```json
{
  "mcpServers": {
    "shopee": {
      "command": "node",
      "args": ["/absolute/path/to/shopee-mcp/build/index.js"]
    }
  }
}
```

On a Linux server without a display, wrap the command with `xvfb-run -a`.

## Recommended AI workflow

For a product with specifications/variants:

1. Search for the product.
2. Call `get_product_variants`.
3. Select the exact `modelId` that matches the requested specification.
4. Call `add_to_cart` with that `modelId` and quantity.
5. Call `get_cart` to verify the resulting cart.

If a product has multiple models and no `modelId` is supplied, `add_to_cart` refuses to guess.

## Safety and privacy

Local browser/session and authenticated debug artifacts are excluded from Git. In particular, do not commit cookies, browser profiles, storage-state files, HAR captures, logs, screenshots containing account data, cart dumps, addresses, or payment information.

The repository's `.gitignore` includes common session/debug artifacts, but that is not a substitute for reviewing commits before pushing. See [`SECURITY.md`](./SECURITY.md).

## Environment variables

| Variable                    | Default                        | Purpose                                                      |
| --------------------------- | ------------------------------ | ------------------------------------------------------------ |
| `SHOPEE_DOMAIN`             | `shopee.co.id`                 | Regional Shopee domain; use `shopee.tw` for Taiwan           |
| `SHOPEE_LOCALE`             | region-derived                 | Browser locale                                               |
| `SHOPEE_TIMEZONE`           | region-derived                 | Browser timezone                                             |
| `SHOPEE_PROFILE_DIR`        | `~/.shopee-mcp/chrome-profile` | Persistent logged-in browser profile                         |
| `SHOPEE_HEADLESS`           | `false`                        | Keep false unless experimenting                              |
| `SHOPEE_CART_WRITE_ENABLED` | `false`                        | Enables `add_to_cart` when explicitly set to `true`          |
| `CACHE_TTL_MS`              | `30000`                        | In-memory product cache lifetime                             |
| `DEBUG`                     | `false`                        | Diagnostic startup logging; must not contain account secrets |
