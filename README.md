# shopee-mcp — buyer cart fork

[English](./README.md) · [繁體中文](./README.zh-TW.md)

This repository is a fork of [`bintangtimurlangit/shopee-mcp`](https://github.com/bintangtimurlangit/shopee-mcp). It keeps the upstream browser-backed product discovery tools and adds **buyer-side cart reading, product-variant inspection, and opt-in Add to Cart support**.

The project is **unofficial** and is not affiliated with Shopee or Sea Limited.

> This fork is currently intended to run **from source**. The upstream npm package does **not** include this fork's cart tools.

## Tools

| Tool                   | Purpose                                             | Account side effect |
| ---------------------- | --------------------------------------------------- | ------------------- |
| `search_products`      | Search Shopee products                              | No                  |
| `get_product_detail`   | Read product details                                | No                  |
| `get_product_variants` | List exact variant/model IDs, stock, and prices     | No                  |
| `get_cart`             | Read the logged-in shopping cart                    | No                  |
| `add_to_cart`          | Add a selected product/model to the cart            | **Yes, opt-in**     |
| `check_login_status`   | Check whether the saved Shopee session is logged in | No                  |

`add_to_cart` is intentionally limited to the shopping cart. This fork does **not** implement checkout, order placement, delivery-address changes, payment-method changes, or payment submission.

## Validation status

CI runs on Node.js 20, 22, and 24 and checks ESLint, Prettier, TypeScript typechecking, build, and offline unit tests.

Shopee is a moving web target: live cart/variant behavior still depends on the current regional Shopee UI and anti-bot behavior. Re-run a local smoke test after Shopee makes major UI changes.

## Why a browser is required

Shopee's buyer web APIs use anti-fraud request signatures generated by Shopee's own web application. The server therefore drives a persistent CloakBrowser/Chromium profile that you log into once, navigates the real Shopee pages, and observes requests/responses generated by Shopee's own frontend.

For cart writes, the server clicks the real product-page **Add to Cart** control and waits for Shopee's `/api/v4/cart/add_to_cart` response. It does not manufacture Shopee's signed private API requests itself.

The browser normally needs to run **headed** because Shopee can detect headless automation.

## Quick start

```bash
git clone https://github.com/DystopiaOwO/shopee-mcp.git
cd shopee-mcp
git checkout feat/cart-tools
npm ci
npm run build
```

### Configure Taiwan Shopee

Copy `.env.example` to `.env` and use:

```env
SHOPEE_DOMAIN=shopee.tw
SHOPEE_HEADLESS=false
SHOPEE_CART_WRITE_ENABLED=false
DEBUG=false
```

When the domain ends in `.tw`, the browser defaults to `zh-TW` and `Asia/Taipei`. You can override these with `SHOPEE_LOCALE` and `SHOPEE_TIMEZONE`.

### Log in once

```bash
npm run login
```

A browser window opens. Log into the Shopee account you want the MCP server to use and follow the terminal prompt. The persistent profile is stored under `~/.shopee-mcp/chrome-profile` by default.

**Treat that directory like a password. Never upload or commit it.**

### Register with an MCP client

After building, point the client at the fork's `build/index.js`.

```json
{
  "mcpServers": {
    "shopee": {
      "command": "node",
      "args": ["C:\\absolute\\path\\to\\shopee-mcp\\build\\index.js"]
    }
  }
}
```

On macOS/Linux desktop, use the appropriate absolute path. On a Linux server without a display, wrap the command with `xvfb-run -a`.

## Enable Add to Cart

Cart mutation is disabled by default. First verify login, search, product variants, and `get_cart`. Then opt in locally:

```env
SHOPEE_CART_WRITE_ENABLED=true
```

Restart the MCP server after changing the flag.

Recommended AI workflow for a product with variants:

1. Call `search_products` or provide a product URL.
2. Call `get_product_variants`.
3. Select the exact `modelId` matching the requested specification.
4. Call `add_to_cart` with that `modelId` and quantity.
5. Call `get_cart` to verify the cart state.

If a product has multiple models and no exact `modelId` is supplied, `add_to_cart` refuses to guess.

## Safety and privacy

Local browser/session and authenticated debug artifacts are excluded from Git. Do not commit cookies, browser profiles, storage-state files, HAR captures, account/cart dumps, logs containing account data, addresses, payment information, or screenshots containing personal information.

Keep `SHOPEE_CART_WRITE_ENABLED=false` when cart mutation is not needed, and only connect this server to AI clients you trust.

See [SECURITY.md](./SECURITY.md) or [SECURITY.zh-TW.md](./SECURITY.zh-TW.md).
