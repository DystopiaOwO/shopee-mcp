## Scripts

| Command                | Description                                                            |
| ---------------------- | ---------------------------------------------------------------------- |
| `npm ci`               | Install exact dependencies from the lockfile                           |
| `npm run login`        | Open a browser window and log into Shopee using the persistent profile |
| `npm run build`        | Compile TypeScript to `build/`                                         |
| `npm run dev`          | Watch mode with `tsx watch src/index.ts`                               |
| `npm run start`        | Run the compiled MCP server                                            |
| `npm run lint`         | Run ESLint                                                             |
| `npm run format`       | Apply Prettier formatting                                              |
| `npm run format:check` | Verify Prettier formatting without modifying files                     |
| `npm run typecheck`    | Strict TypeScript checking with no emit                                |
| `npm run test:unit`    | Offline unit tests; no login/display required                          |
| `npm test`             | Live smoke test; requires a login and graphical display                |

CI validates Node.js 20, 22, and 24 with lint, Prettier check, typecheck, build, and offline unit tests.

```text
  api/
    client.ts       # page navigation and Shopee response capture

  smoke.ts          # live browser smoke test
```

## Why a browser is required

Shopee's buyer endpoints are guarded by anti-fraud request signatures generated by Shopee's own web application. The project therefore drives CloakBrowser/Chromium with a logged-in persistent profile and lets Shopee's own frontend generate the signed requests.

Read operations navigate real Shopee pages and capture the resulting JSON responses. `add_to_cart` uses the real product-page UI and observes the resulting `/api/v4/cart/add_to_cart` response instead of constructing a private signed request manually.

The browser normally runs headed. On Linux servers, use a virtual display such as `xvfb`.

## Cart-tool design

### `get_product_variants`

The tool exposes exact model IDs, option labels, stock, and prices. It supports both current variant indexes under `models[].extinfo.tier_index` and the legacy `models[].tier_index` shape.

### `get_cart`

The tool reads the current logged-in cart and extracts product links, names, quantities, and useful visible cart-row text. Because Shopee's DOM can change, selectors should favor stable URLs, accessible roles/names, attributes, and structural relationships over obfuscated CSS classes.

### `add_to_cart`

The tool is disabled unless:

```env
SHOPEE_CART_WRITE_ENABLED=true
```

If multiple models exist and the caller does not supply an exact `modelId`, the tool refuses to guess. It does not implement checkout or payment actions.

## Recommended validation flow

After changing browser/cart code:

```bash
npm run lint
npm run format:check
npm run typecheck
npm run build
npm run test:unit
```

Then perform a live regional smoke test with a trusted test item:

1. Keep `SHOPEE_CART_WRITE_ENABLED=false`.
2. Verify `check_login_status`.
3. Verify `search_products` and `get_product_detail`.
4. Verify `get_product_variants` on a multi-variant product.
5. Verify `get_cart` against a non-empty cart.
6. Only if write testing is required, enable `SHOPEE_CART_WRITE_ENABLED=true`.
7. Add quantity `1` of an explicitly selected model.
8. Call `get_cart` again to verify the resulting state.

Do not use a live test to exercise checkout, order placement, address changes, or payment.

## Taiwan-specific checks

For `SHOPEE_DOMAIN=shopee.tw`, verify:

- browser locale defaults to `zh-TW`;
- timezone defaults to `Asia/Taipei`;
- product URLs stay on `shopee.tw`;
- TWD prices are displayed as TWD/NT$, not IDR;
- Traditional Chinese Add to Cart labels are recognized;
- current Taiwan cart DOM extraction still works.

## Build output

`npm run build` emits JavaScript under `build/`. The directory is gitignored and should be regenerated locally/CI.

## Security during development

Never commit or attach real cookies, browser profiles, storage state, HAR files, authenticated API dumps, cart dumps, addresses, phone numbers, payment details, or screenshots containing personal information. Tests and fixtures must use synthetic data.

See [SECURITY.md](../SECURITY.md).
